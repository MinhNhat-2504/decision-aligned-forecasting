# Decision-Aligned Demand Forecasting for Last-Mile Delivery

Code and numerical results for the paper

> **Forecast Value Is a Property of the Decision: Calibrated Quantile Demand Forecasting
> for Urban Last-Mile Capacity and Routing**
> Kien Pham Xuan, Nhat Trinh Ngoc Minh, Linh Nguyen Thi My
> *International Journal of Analysis and Applications*, accepted 2026 (in press, article ID ijaa5688).

The DOI will be added here once the article is published.
A Vietnamese version of this file is in [README.vi.md](README.vi.md).

## What the paper shows

Forecasting studies usually read lower prediction error as higher operational value.
For capacity planning that inference is unsafe. The cost-minimising commitment is a
demand **quantile**, and the level of that quantile is the **target service level**. An
operator who plans capacity from a median forecast has silently chosen a 50% service
target.

We feed the **same forecasts** into two decisions that consume different things, over
263 New York City zones and 39.0 million taxi trips from two services. The two decisions
give opposite answers.

| Decision | What it needs from the forecast | Result |
|---|---|---|
| Capacity commitment (newsvendor, 9:1 penalty) | a calibrated tail quantile | capacity cost down **42–51%**; fill rate 94.9% → 98.9% (yellow) and 86.8% → 97.4% (green) |
| Top-K zone selection | only a ranking | learned models beat a weekly historical average by **under 0.15 percentage points** |

Three further findings, two of them negative, are reported in full:

- The model with the lowest error is not the model with the lowest cost.
- No architecture ranks stably across the two demand regimes, and no hand-designed
  graph relation gives a replicable benefit.
- What transfers is the **decision layer**: a monotone quantile head with conformal
  calibration moves unchanged between backbones, and reproduces 40–54% cost reductions
  on five external corpora (Porto, Olist, Amazon, Meituan, Cainiao-LaDe).

## Repository layout

```
src/             43 Python scripts: data, models, experiments, analysis
outputs/         result tables (.csv / .json), yellow taxi and external corpora
outputs_green/   result tables, green taxi
figures/         figures used in the paper, all generated by src/figures.py
figures_green/   the same figures for green taxi
run_*.sh         staged pipelines (bash)
run_*.ps1        long-running robustness suites (PowerShell)
```

The result tables behind the paper are in `outputs/` and `outputs_green/`, so you can
inspect the numbers without running anything.

### Core pipeline

| File | Role |
|---|---|
| `src/config.py` | all settings: time splits, horizons, graph and training hyperparameters |
| `src/data_build.py`, `src/data_build_green.py` | hourly zone-level demand from raw trips |
| `src/graphs.py` | three graph relations: geographic, road network, origin–destination flow |
| `src/dataset.py` | sliding windows, chronological split, seasonal-residual targets |
| `src/models.py` | GCN, GraphSAGE, GAT, ST-MRGAT, DCRNN, Graph WaveNet, MLP, LSTM, monotone quantile head |
| `src/train_eval.py` | training loop, baselines, conformalised quantile regression |
| `src/operations.py` | the two decisions: newsvendor capacity and top-K zone selection |

### Analyses

| Topic | Scripts |
|---|---|
| Statistical tests | `dm_test.py` (Diebold–Mariano), `multiplicity.py` (Holm / Benjamini–Hochberg) |
| Calibration | `mondrian_cqr.py`, `calibration_slices.py` |
| Decision robustness | `decision_robustness.py`, `decision_selection.py`, `decision_focused.py`, `capacity_matched.py`, `economic_sensitivity.py` |
| Routing | `ksweep.py`, `routing_robustness.py`, `vrp_constrained.py`, `vrp_exact.py`, `execution_deviation.py` |
| Noise floor | `nondeterminism.py` |
| Interpretation | `analysis.py` (relation-level attention) |
| External validation | `external_porto.py`, `external_porto_neural.py`, `olist_order_arrival.py`, `amazon_parcel_eval.py`, `amazon_parcel_postprocess.py`, `meituan_end_to_end.py`, `lade_shanghai_capacity.py` |
| Figures and merging | `figures.py`, `merge_results.py` |

`external_chicago.py` is a small extra check that is not reported in the paper.

## Reproducing the results

### 1. Environment

```bash
pip install -r requirements.txt
```

Install PyTorch separately for your CUDA version, following the
[official instructions](https://pytorch.org/get-started/locally/). The experiments in
the paper ran on `torch 2.5.1+cu121`.

### 2. Data

No data is included. All sources are public third-party datasets with their own
licences, so they are not redistributed here.

**Downloaded by a script in this repository:**

| Dataset | Script | Used for |
|---|---|---|
| Porto taxi (UCI) | `external_porto.py` | a second city |
| Olist (Brazilian e-commerce) | `fetch_olist_orders.py` | real parcel order arrivals |
| Amazon Last Mile Routing Challenge | `fetch_amazon_parcel.py` | real routes and vehicle capacity |
| Meituan (INFORMS TSL challenge) | `fetch_meituan_delivery.py` | same-order creation-to-delivery records |
| Cainiao-LaDe | `fetch_lade_parcel_gps.py` | 184 days of parcel history with GPS events |

**Placed by hand.** There is no download script for these three sources.

| Dataset | Where the code expects it |
|---|---|
| NYC yellow taxi, Jan–Mar 2016, legacy CSV release with pickup and drop-off coordinates; NYC taxi zone polygons; OpenStreetMap street network for New York | one zip archive, path given by the `GAT_ZIP` environment variable; member paths are listed in `src/config.py` |
| NYC green taxi, Jan–Mar 2016, parquet files from the [TLC trip record page](https://www.nyc.gov/site/tlc/about/tlc-trip-record-data.page) | `data/raw2/green_2016-01.parquet`, `green_2016-02.parquet`, `green_2016-03.parquet` |
| Planned-versus-driven delivery routes (the route deviation corpus cited in the paper) | `data/raw3/Last-mile delivery route deviations dataset planned vs. actual routes/routes_performance.xlsx` |

```bash
export GAT_ZIP="/path/to/archive.zip"
```

The yellow taxi build assigns each trip to a zone by point-in-polygon, so it needs the
legacy files that carry coordinates.

### 3. Build the datasets

```bash
python src/data_build.py          # yellow demand + zones.csv
python src/graphs.py              # the three graph relations
python src/data_build_green.py    # green demand + green graphs (run after the two above)
```

### 4. Run the experiments

```bash
bash run_all.sh      # yellow: benchmark (5 seeds), ablation, decisions, figures, attention
bash run_gpu.sh      # adds DCRNN and Graph WaveNet; full green benchmark; downstream analysis
bash run_gwnq.sh     # Graph WaveNet with the quantile head, then merge and re-analyse
bash run_3a.sh       # Mondrian (group-conditional) conformal calibration
bash run_taskB.sh    # model selection by decision cost
```

The robustness suites are PowerShell scripts: `run_robustness.ps1` and
`run_final_jobs.ps1`.

Switch dataset or run a subset with:

```bash
DATASET=green python -u src/train_eval.py --seeds 3
python -u src/train_eval.py --models GraphWaveNet-Q
```

The full chain takes about **12 hours on one GPU**. The downstream analyses
(`dm_test.py`, `operations.py`, `ksweep.py`, `multiplicity.py`) run on CPU in minutes.

## Things to know before reading the numbers

**Results are not bit-reproducible.** GPU reduction kernels are non-deterministic, so
the same configuration with the same seed gives slightly different results. We measured
that spread with `src/nondeterminism.py`: about **0.83%** of MAE on yellow and **0.70%**
on green. This is the resolution limit of the study. A difference smaller than it cannot
be attributed to any intervention, and we grade our own claims against it.

**No label leakage.** Splits are chronological with no shuffling, and each sample is
assigned to a split by the time of its target. The conformal calibration block lies
strictly after the early-stopping block and is disjoint from it.

**Predictions and weights are not stored.** Saved prediction tensors and model
checkpoints are excluded because of their size. Regenerate them by running the pipeline.

**Negative results are kept.** The repository reproduces the results that did not
support the initial hypothesis as well as those that did.

## Why this repository exists

The project started from an existing pipeline. The first step was to audit it with
`src/audit_original.py`, which found:

```
corr(demand, historical_trip_count) = 1.0000000000
R² of a linear regression           = 1.0
```

The input feature **was the label**. The model was predicting what it had already been
given, so every number from the earlier version was meaningless and the pipeline was
rebuilt from scratch.

The audit script is kept for the record. It reads the output files of that earlier
pipeline, through the `GAT_ORIG` environment variable, and those files are not part of
this repository.
